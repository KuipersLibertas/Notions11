## Issues Found

### HIGH — Fix before next launch/promotion

**1. Broken `tsc` binary in node_modules**
`node_modules/.bin/tsc` is a corrupt regular file (45 bytes, dated Dec 2023) instead of a proper symlink to `../typescript/bin/tsc`. Running `npx tsc` fails with `Cannot find module '../lib/tsc.js'`. If any CI pipeline calls `npm run tsc` or `npx tsc`, it silently fails.

Workaround: run `node node_modules/typescript/lib/tsc.js --noEmit` directly (it works fine). Fix: delete the corrupt wrapper and recreate the symlink.

**2. Database CSV exports sitting in repo root (untracked, not gitignored)**
These files are in the repo root and not covered by `.gitignore`:
```
daily_downloads.csv       — analytics data
file_list_user.csv        — ALL link records (slugs, original URLs, password hashes)
ip_tracker.csv            — IP addresses and geolocations of your users' visitors
users.csv                 — user accounts
paid_links.csv
paid_membership.csv
password_reset_tokens.csv — active reset tokens
personal_access_tokens.csv — potentially active auth tokens
```
These are almost certainly one-off migration exports. They must never be committed — especially `users.csv`, `ip_tracker.csv`, `password_reset_tokens.csv`, and `personal_access_tokens.csv`. Adding them to `.gitignore` now closes the risk.

### MEDIUM — Address this sprint

**3. `constants.ts` missing `Notion: 3` in `LinkType`**
`LinkType` only defines `DropBox: 1, GoogleDrive: 2` — a Passdropit leftover. Notions11 hardcodes `service: 3` directly in `EnterLink/index.tsx` without referring to a constant. This isn't a runtime bug but it's confusing for any future developer (or agent) reading the code. Fix: add `Notion: 3` and use `LinkType.Notion` in the one place it's hardcoded.

**4. One-off migration scripts and stale images at repo root (untracked)**
`migrate.mjs`, `migrate-logos.mjs`, `newlogo1.png`, `newlogo2.png`, `newlogo3.png`, `screenshot.jpg`, `favicon.jpg`, `logos.zip` are all untracked one-off files at the root. Add them to `.gitignore` (they're migration artifacts, not project files).

### LOW — Background/nice-to-have

**5. `api/session/route.ts` has commented-out auth check**
The 401 guard is commented out. The endpoint currently returns `{authenticated: false, session: null}` for unauthenticated callers, which is harmless — but the commented code is misleading. Either remove the comment or reinstate the guard.

**6. `backend/` folder is in the repo**
The full Laravel app is committed. Only `backend/app/vendor/` is gitignored. This is ~several hundred files of dead PHP that adds noise to `git log` and repo size. It's excluded from Vercel so it's not a live issue, but it's worth a one-time `git rm -r backend/` to clean history.

**7. `tsc` binary is broken (see #1) — also means `npm run lint` via webpack ESLint may have similar issues**
Run `npm run lint` to confirm ESLint is wiring up correctly in dev mode.
